Đề xuất tích hợp RedThread ↔ LAN Agent máy thêu

Mục tiêu: chuyển file thiết kế qua mạng LAN, tự động dọn file sau khi hoàn thành và đồng bộ trạng thái vận hành máy về RedThread.

Phiên bản đề xuất: 1.0Ngày: 24/08/2026Trạng thái: Chờ hai bên xác nhận

1. Kết luận quan trọng

RedThread và LAN Agent là hai hệ thống độc lập. RedThread chạy trên cloud nên không thể truy cập trực tiếp IP nội bộ hoặc thư mục của máy thêu.

File phải được xóa tại máy thêu bởi LAN Agent. RedThread chỉ phát sinh yêu cầu xóa; LAN Agent nhận lệnh, xóa file trong LAN rồi gửi kết quả DELETED hoặc DELETE_FAILED về RedThread.

2. Kiến trúc đề xuất

RedThread CloudQuản lý đơn hàng, Batch, QR, file thiết kế, hàng đợi công việc và lịch sử trạng thái.
⇄
LAN AgentTool của bên máy thêu, chạy trên PC tại xưởng; chủ động gọi API RedThread.
⇄
Máy thêuNhận/xóa file qua SMB, FTP, hot-folder hoặc SDK của hãng máy.

LAN Agent nên chủ động kết nối ra internet bằng HTTPS để lấy việc. RedThread không cần mở kết nối từ cloud vào LAN, không lưu tài khoản SMB/FTP của xưởng và không cần biết IP riêng của máy thêu.

4. Ba luồng nghiệp vụ

1

Gửi file

Khi người dùng tạo Batch, chọn máy và bấm “Send to Machine”, RedThread tạo deployment. Agent nhận job, tải file và chép sang máy.

2

Xóa file

Khi đạt mốc hoàn thành đã thống nhất, RedThread tạo lệnh xóa. Agent xóa đúng file đã triển khai rồi báo kết quả.

3

Monitor máy

Agent gửi heartbeat/status định kỳ. RedThread tách status máy khỏi status đơn hàng và tính thời gian chạy, dừng, lỗi.

4.1. Gửi file thiết kế

RedThread: tạo Batch + chọn Machine → RedThread: tạo deployment QUEUED → LAN Agent: poll và claim job → LAN Agent: tải manifest + file, kiểm checksum → LAN Agent: chép sang máy bằng giao thức được hỗ trợ → LAN Agent: báo COPIED / VERIFIED hoặc FAILED

Vòng đời đề xuất: QUEUEDCLAIMEDDOWNLOADINGCOPIEDVERIFIEDFAILED

4.2. Xóa file sau khi hoàn thành

QR/event hoàn thành trên RedThread → RedThread: tạo DELETE_PENDING cho deployment → LAN Agent: nhận lệnh và đối chiếu machine + remote path → LAN Agent: xóa file tại máy thêu → LAN Agent: báo DELETED hoặc DELETE_FAILED
Cần chốt mốc xóa: QR đầu tiên hiện mang nghĩa “bắt đầu sản xuất”, không được dùng để xóa. Hai bên cần chọn: xóa khi item hoàn thành, khi cả Batch hoàn thành, hoặc dùng một QR/event riêng tại máy mang nghĩa “thêu xong”. Khuyến nghị an toàn: chỉ xóa khi toàn bộ công việc dùng file đó đã hoàn thành.

4.3. Theo dõi trạng thái máy

Status của máy độc lập với status của Batch/đơn hàng:

OFFLINEIDLERUNNINGPAUSEDERROR

Agent gửi heartbeat khoảng 30 giây/lần, gồm status, batch/file hiện tại, thời điểm bắt đầu status và mã lỗi nếu có. Nếu không nhận heartbeat quá ngưỡng cấu hình, RedThread suy ra OFFLINE. Việc nhận diện ERROR tự động chỉ khả thi khi máy có API/SDK/log mà Agent đọc được.

5. API contract sơ bộ

Đây là contract để hai bên thảo luận, chưa phải đặc tả cuối cùng. Agent xác thực bằng token riêng theo workspace/agent; mọi request dùng HTTPS.

POST /api/v1/lan-agents/heartbeat
{
  "agentId": "agent-factory-a",
  "machines": [{
    "machineId": "machine-01",
    "status": "RUNNING",
    "currentBatchId": "batch-042",
    "currentFile": "B042_design.dst",
    "statusSince": "2026-08-24T13:58:00+07:00",
    "errorCode": null
  }]
}

GET  /api/v1/lan-agents/{agentId}/jobs?after={cursor}
POST /api/v1/deployments/{deploymentId}/claim
GET  /api/v1/deployments/{deploymentId}/manifest
POST /api/v1/deployments/{deploymentId}/events

// event payload ví dụ

6. Quy tắc kỹ thuật bắt buộc

  • Idempotency: gửi lại cùng eventId hoặc xử lý lại cùng job không được tạo file trùng, xóa nhầm hay đổi trạng thái sai.
  • Claim/lease: một job chỉ do một Agent xử lý tại một thời điểm; lease hết hạn thì có thể claim lại.
  • Kiểm file: Agent kiểm kích thước và SHA-256 trước khi chép; chỉ báo VERIFIED sau khi xác minh file đích.
  • Xóa an toàn: chỉ xóa đúng remotePath của deployment, không nhận đường dẫn tùy ý ngoài thư mục cấu hình.
  • Offline/retry: khi mất mạng, Agent lưu hàng đợi cục bộ và callback lại; RedThread lưu lỗi và cho phép retry.
  • Bảo mật: token có thể thu hồi/rotate; không gửi mật khẩu SMB/FTP lên RedThread; log không chứa secret.
  • Audit: lưu ai tạo lệnh, Agent nào nhận, thời gian copy/xóa, checksum và thông báo lỗi.

7. Thông tin cần bên LAN Agent xác nhận

  1. Hãng và model chính xác của từng máy thêu.
  2. Cơ chế nhận file: SMB, FTP/SFTP, hot-folder, vendor API/SDK hay phương án khác.
  3. Xác nhận quy ước cho các file RedThread gửi sang: file thêu DST và ảnh tham chiếu PNG hoặc JPG; đồng thời cho biết giới hạn tên file, ký tự và độ dài.
  4. Máy có API/SDK/log để đọc RUNNING, IDLE, PAUSED, ERROR và error code không?
  5. Một PC Agent quản lý bao nhiêu máy? Agent có chạy 24/7 và tự khởi động lại không?
  6. File phải xóa khi một item xong, toàn bộ Batch xong, hay theo event “thêu xong” riêng?
