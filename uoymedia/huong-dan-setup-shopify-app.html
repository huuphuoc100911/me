Tài liệu đi từng bước: tạo tài khoản, lấy key, tạo database, cấu hình Render, cài app vào store, quản lý nhiều app từ một codebase và xử lý lỗi.

Không ghi mật khẩu hoặc secret thật trong tài liệu. Lưu secret trong password manager và Render Environment.

1 Hiểu hệ thống trong 2 phút

Mỗi dự án (store) chạy trên một Shopify app riêng, một Render service riêng và một Neon DB riêng — tất cả dùng cùng một GitHub repo. Không cần copy code.

2 Chuẩn bị tài khoản và phần mềm

Tất cả đều có gói miễn phí:

  • Tài khoản GitHub có quyền đọc/push repository
  • Tài khoản Shopify Partners (partners.shopify.com) và ít nhất một development store để test
  • Tài khoản Render (render.com)
  • Tài khoản Neon (neon.tech)
  • Trên máy: Git, Node.js ≥ 22.12, pnpm và Shopify CLI

Kiểm tra trong terminal:

cd ~/Documents/Project/shopify-bulk-editor
nvm use
node -v     # phải in v22.x.x
pnpm -v
shopify version
Bảo mật: Không gửi ảnh chứa Client secret, DATABASE_URL, CRON_SECRET hoặc access token lên channel công khai.

3 Tạo Shopify app mới trong Partners

Mỗi dự án / store cần một Shopify app riêng với Client ID riêng.

  1. Đăng nhập partners.shopify.com → Apps → Create app.
  2. Chọn Create app manually, đặt tên ví dụ uoy-ginger-bulk-edit.
  3. Mở app vừa tạo → API credentials / Client credentials.
  4. Copy Client ID — đây là SHOPIFY_API_KEY.
  5. Reveal/copy Client secret — đây là SHOPIFY_API_SECRET. Lưu vào password manager ngay.
Không copy Client secret vào GitHub. Nếu từng lộ secret, phải rotate trong Shopify Dashboard rồi cập nhật Render.

3.1 Lặp lại cho mỗi dự án mới

Ví dụ với 2 store: tạo app uoy-ginger-bulk-edit và uoy-flagwix-bulk-edit. Mỗi app có Client ID riêng — ghi lại để điền vào toml ở bước 4.

4 Tạo file config toml cho từng app

Trong repo có thể có nhiều file shopify.app.<tên>.toml, mỗi file ứng với một Shopify app. Không chỉnh sửa shopify.app.toml gốc nếu đang dùng.

4.1 Tạo file mới cho từng dự án

Ví dụ tạo shopify.app.ginger.toml:

client_id = "CLIENT_ID_CỦA_APP_GINGER"
name = "UOY Bulk Edit - Ginger"
application_url = "https://uoy-ginger-bulk-edit.onrender.com"
embedded = true

[build]
automatically_update_urls_on_dev = false

[webhooks]
api_version = "2026-07"

  [[webhooks.subscriptions]]
  uri = "/webhooks/app/uninstalled"
  topics = [ "app/uninstalled" ]

  [[webhooks.subscriptions]]
  uri = "/webhooks/app/scopes_update"
  topics = [ "app/scopes_update" ]

  [[webhooks.subscriptions]]
  uri = "/webhooks/customers/data_request"
  compliance_topics = [ "customers/data_request" ]

  [[webhooks.subscriptions]]
  uri = "/webhooks/customers/redact"
  compliance_topics = [ "customers/redact" ]

  [[webhooks.subscriptions]]
  uri = "/webhooks/shop/redact"
  compliance_topics = [ "shop/redact" ]

[access_scopes]
scopes = "write_products,write_inventory"
optional_scopes = [ ]
use_legacy_install_flow = false

[auth]
redirect_urls = [ "https://uoy-ginger-bulk-edit.onrender.com/auth/callback" ]

Làm tương tự shopify.app.flagwix.toml, thay client_id, name, application_url và redirect_urls bằng giá trị của app Flagwix.

4.2 Deploy config lên Shopify Partners

Sau khi điền đúng client_id, chạy lần lượt:

cd ~/Documents/Project/shopify-bulk-editor
nvm use

shopify app deploy --config ginger
shopify app deploy --config flagwix

Lệnh này cập nhật App URL, redirect URL, scopes và webhook vào Shopify Partners — không cần vào dashboard bấm thủ công. Chạy lại lệnh mỗi khi thay đổi URL, scope hoặc webhook.

Không nhầm file. Kiểm tra CLI in ra đúng app name trước khi confirm. Dùng --config để tránh ghi đè app khác.

5 Tạo PostgreSQL trên Neon

Mỗi dự án nên có một Neon project riêng để cách ly dữ liệu hoàn toàn.

  1. Đăng nhập neon.tech → New project.
  2. Đặt tên, ví dụ uoy-ginger; chọn region gần Render service.
  3. Mở project → Connect → chọn database production, bật Pooled connection.
  4. Copy toàn bộ connection string.
  5. Lặp lại cho dự án Flagwix: project uoy-flagwix.

Dạng connection string:

postgresql://USER:PASSWORD@HOST-pooler.neon.tech/DATABASE?sslmode=require
Không tự sửa ký tự trong URL. Khi dán vào Render, không thêm dấu nháy " hay ' bao quanh.

5.1 Schema được tạo tự động

Dockerfile chạy pnpm run docker-start → gọi:

prisma generate
prisma migrate deploy
react-router-serve ./build/server/index.js

Migration trong prisma/migrations tự áp dụng mỗi khi container khởi động — không cần làm thêm.

6 Biến môi trường — mỗi Render service một bộ riêng

Không dùng chung một bộ env vars cho nhiều service. Mỗi Render service phải có bộ riêng trong tab Environment của service đó.

KeyLấy giá trị ở đâuLưu ý
SHOPIFY_API_KEYShopify Partners → app → Client credentials → Client IDKhác nhau cho từng app/dự án.
SHOPIFY_API_SECRETShopify Partners → app → Client credentials → Client secretBí mật; tuyệt đối không commit.
SHOPIFY_APP_URLURL public của Render service, ví dụ https://uoy-ginger-bulk-edit.onrender.comKhông có / cuối. Phải khớp toml.
DATABASE_URLNeon → project → Connect → Pooled connection stringBắt đầu postgresql://; khác nhau cho từng dự án.
SCOPESPhải khớp [access_scopes] trong file tomlwrite_products,write_inventory
CRON_SECRETTự tạo bằng openssl rand -hex 32Tạo một chuỗi riêng cho từng service.

File .env chỉ dùng cho local dev. Trên Render không cần và không nên có file .env — toàn bộ secret đặt trong Render Environment dashboard.

7 Đưa source code lên GitHub

Cả 2 dự án dùng chung repo. Commit file toml của từng app — chúng không chứa secret:

cd ~/Documents/Project/shopify-bulk-editor
git add shopify.app.ginger.toml shopify.app.flagwix.toml
git status
git add <các-file-code-cần-commit>
git commit -m "Add multi-app config"
git push origin main
Không stage mù quáng. Chắc chắn .env nằm trong .gitignore. Chạy git status — nếu thấy .env trong danh sách sắp commit thì dừng lại ngay.

8 Tạo Render Web Service bằng Docker

Làm các bước sau cho từng dự án (lặp lại cho Ginger, Flagwix, …):

  1. Đăng nhập render.com → New + → Web Service.
  2. Chọn Git Provider, kết nối GitHub và chọn repo shopify-bulk-editor.
  3. Đặt tên service khớp với dự án, ví dụ uoy-ginger-bulk-edit.
  4. Chọn đúng production branch (main).
  5. Runtime chọn Docker — Render tự đọc Dockerfile ở root.
  6. Chọn region gần Neon; chọn plan phù hợp.
  7. Ở phần Environment Variables, thêm đủ 6 biến của dự án này (bộ riêng).
  8. Bấm Create Web Service, theo dõi Logs đến khi trạng thái Live.
Không cần nhập Build Command/Start Command thủ công. Dockerfile đã build React Router và chạy pnpm run docker-start.

8.1 Auto-Deploy

Render service → Settings → Build & Deploy → Auto-Deploy:

  • On Commit — push vào branch là Render deploy ngay (khuyến nghị khi chưa có CI).
  • After CI Checks Pass — chỉ deploy khi CI thành công.
  • Off — phải bấm Manual Deploy mỗi lần.
Khi có nhiều service từ cùng một repo, mỗi push lên main sẽ trigger deploy cho tất cả service. Nếu chỉ muốn deploy một service, dùng Manual Deploy trên service đó.

9 Cài app vào development store

  1. Vào Shopify Partners → chọn đúng app (Ginger hoặc Flagwix).
  2. Chọn Test your app / Test on development store.
  3. Chọn store tương ứng (ví dụ gingerglow.myshopify.com).
  4. Bấm Install, xem kỹ các quyền rồi chấp thuận.
  5. Mở Shopify Admin → Apps → tên app.
Thành công khi: App mở trong Shopify Admin, không báo OAuth/redirect error; Render Logs có request; Neon xuất hiện bản ghi session sau lần cài đầu.
Mỗi app chỉ cài vào đúng store tương ứng. App Ginger cài vào gingerglow.myshopify.com, app Flagwix cài vào flagwix.myshopify.com.

10 Quy trình cập nhật app mỗi ngày

Trường hợp A — chỉ sửa giao diện hoặc logic backend

git status
git add <các-file-code-cần-commit>
git commit -m "Describe the change"
git push origin main

Chờ Render deploy thành Live, sau đó reload app. Không cần cài lại app. Tất cả service từ cùng repo sẽ deploy cùng lúc nếu Auto-Deploy đang bật.

Trường hợp B — thay đổi database

pnpm prisma migrate dev --name ten_thay_doi
git add prisma
git commit -m "Add database migration"
git push origin main

Render startup tự chạy prisma migrate deploy trên từng DB. Backup dữ liệu trước migration có nguy cơ xoá/đổi kiểu cột.

Trường hợp C — đổi scopes, webhook, URL của một app cụ thể

# Sửa file toml của app cần thay đổi, rồi:
shopify app deploy --config ginger

git add shopify.app.ginger.toml
git commit -m "Update Ginger app config"
git push origin main

Nếu thêm quyền, merchant có thể phải duyệt quyền mới khi mở app.

Trường hợp D — thêm dự án mới (store mới)

  1. Tạo Shopify app mới trong Partners (bước 3).
  2. Tạo Neon project mới (bước 5).
  3. Tạo file shopify.app.<tên>.toml (bước 4).
  4. Tạo Render service mới, set env vars bộ riêng (bước 6, 8).
  5. Chạy shopify app deploy --config <alias>.
  6. Cài app vào store tương ứng (bước 9).

11 Cấu hình chạy task theo lịch (Cron)

Route /api/cron không tự chạy — cần scheduler gửi POST định kỳ:

curl -X POST \
  https://<render-service-url>/api/cron \
  -H "x-cron-secret: <CRON_SECRET_CỦA_SERVICE_ĐÓ>"

Tạo một scheduler riêng cho từng Render service. Có thể dùng cron-job.org (miễn phí), GitHub Actions scheduled workflow, hoặc scheduler riêng. Chu kỳ đề xuất: 5 phút.

Không đặt CRON_SECRET trong repo/workflow public. Mỗi service có CRON_SECRET riêng; dùng secret store của dịch vụ scheduler.

12 Chạy dự án trên máy để phát triển

Local cần tunnel HTTPS. Dùng hai terminal, chỉ định đúng config app đang dev:

Terminal 1 — tunnel

cloudflared tunnel --url http://localhost:3458 --no-autoupdate

Copy URL dạng https://xxxxx.trycloudflare.com.

Terminal 2 — Shopify CLI (chỉ định app cần dev)

cd ~/Documents/Project/shopify-bulk-editor
nvm use
pnpm install
pnpm shopify app dev --config local \
  --tunnel-url https://xxxxx.trycloudflare.com:3458

Thay shopify.app.local.toml bằng file config tương ứng nếu cần dev với app Ginger/Flagwix. Mỗi lần quick tunnel khởi động lại, URL đổi — chỉ dùng cho dev.

14 Checklist trước khi bàn giao từng dự án

  • GitHub repo không chứa .env hoặc secret.
  • File shopify.app.<tên>.toml của app này đã có trong repo với đúng client_id và URL.
  • Đã chạy shopify app deploy --config <alias>.
  • Render service đúng repo, đúng branch, đủ 6 env vars riêng của dự án này.
  • Deploy mới nhất có trạng thái Live.
  • URL Render mở được và khớp SHOPIFY_APP_URL trong env.
  • App mở được trong Shopify Admin của đúng store.
  • Neon DB đúng project có dữ liệu session/shop và migration đã hoàn tất.
  • Scheduler gọi /api/cron của service này thành công (nếu dùng scheduled tasks).
  • Đã ghi lại nơi lưu: Client ID/Secret, Neon connection string, CRON_SECRET của dự án này.
